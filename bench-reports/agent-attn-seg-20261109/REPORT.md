# 混批逐段 attn（v9 段级 + run 合并）：Agent ITL −64%、满载 +3.7%（2026-11-09）

## 一、改动（commit 本刀）

`attn_long` 新增混批/多段逐段路径（默认开，`WEIN_ATTN_MIXSEG=0` 回退）：

- **≥64 行段**：64 对齐主段走 v9（或 v5，`WEIN_ATTN_V9` 沿用）；段内 16 对齐余段走 v4。
- **段内视图**：`seqs` 一律取 `scr.seqs_zero`（t_max×4B 全 0 缓冲，进入路径时 `zero_on`）
  的切片；`bt` narrow 到该段请求的行（`rid * bpr * 4`，1 行）——**v9 对 seq≠0 的行算错**
  （上一刀定案），全 0 + 行视图 = 已验证修法（attn_mix_probe ②：rel2=1.172e-3）。
- **run 合并**：段尾 <16 行与 decode 段按**连续区间**合并成 run 走 online 老路（真 seqs；
  online 按行寻址行独立，o41 批形无关合同）。全 decode 稳态 = 单 run 整批 online =
  **现状零退化**。
- **cfg 按整批 t 选**（不按 run 行数）：同批所有 online 调用同档 ⇒ 与现状整批一遍位级同。
- 两个调用点：主路径传 `Some((&spans.count, &spans.rid))`；MTP 草稿层传 `None`（行为不变）。

中途修一个真 bug：bt 布局是 **[128 请求, bpr 页]**（行=seq id），不是 token 行——
首版按 token 行 narrow 直接越界 panic（b2 抓住）；`SpanTabs.rid` 正是所需映射。
