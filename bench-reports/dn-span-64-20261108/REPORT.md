# deltanet chunked 门槛 256 → 64：Agent ITL −28%（2026-11-08）

## 一、改动（一处常量 + 一个 env 旋钮）

```rust
// crates/wein-exec/src/qwen.rs
const DN_CHUNK_MIN_SPAN: u32 = 64;   // 旧值 256；WEIN_DN_CHUNK_MIN 可覆盖（A/B）
```

Agent 每轮新增 span ≈ **190 token**，旧门槛 256 让它走不了 chunked（10.8µs/token），
只能走老路（2.36µs/token/层 × 24 层 ≈ 10.8ms/步）。门槛降到 BT 的最小单位（64）后，
190 token 切成 3 个 chunk，grid = 行×32 vh×4 vsplit = 128 块（铺满 128 SM）。

## 二、读数（c=16×6，8192 ctx，kv6144，chunk2048，**每发前清前缀，三发取中位**）

| 配置 | turns/s | 热 TTFT | ITL p50 | 命中 |
|---|---|---|---|---|
| legacy（门槛 256） | 1.59 / 1.64 / 1.52 | 4355 / 3915 / 4680 | **52.50 / 52.76 / 52.59** | 23 / 27 / 19% |
| **门槛 64** | 2.45 / 2.25 / 1.90 | 2287 / 3527 / 4577 | **37.65 / 37.41 / 40.57** | 30 / 31 / 20% |

**ITL −28%（52.6 → 37.6ms）、turns/s +40%（1.59 → 2.25 中位）**，TTFT 与命中同向略好。

## 三、满载代价（battery，同日）

| | 图档满载 tps | ITL p50 | 轻载 c=4 |
|---|---|---|---|
| 本刀 | 4323.8 | 20.86 | 11.56 |
| 上一轮（快照策略） | 4430.8 | 20.21 | 11.03 |

满载 **−2.4% tps / +0.65ms ITL**（+3%）：满载爬坡期也有 64-256 token 的 prefill 碎片，
走 chunked 要多付 4 个 kernel launch + scratch。**用 +3% 满载换 −28% Agent ITL，值得**，
但门槛是全局常量，没有按场景分流——留作后续（按 `批内 decode 行数` 或 span 数分流）。

## 四、测量陷阱（两条，都已造成错误结论）

1. **`POST /reset_prefix_cache` 要确认生效**。有一次清缓存后读出色 13.6ms / 3.6 turns/s
   （比真实好 2.7×），事后无法复现——大概率是那次 reset 没落地（radix 仍完整）。
   **agent 场景每次测量前必须清前缀，且连清后两次读数一致才算数。**
2. **第一发含冷启动**（CUDA 图首次捕获、池/槽首次分配）：本刀第一发 38.8ms、后两发 37.4ms
   （差 4%，可接受），但更早那次出现 52.5 vs 37.7 的 28% 差 ⇒ **至少三发取中位**。

## 五、验收

* `cargo test --release -p wein-exec`：8 + 1 + 3 + **23** + 2 + 4 全绿（含 o35 chunked 容差档
  在更大的 span 集合上仍然 rel2 ≤ 3e-3）。
* `WEIN_DN_CHUNK_MIN=256` 回退到旧行为（A/B 已验证）。
* 6009 冷未重测：其 chunk 是 2048，与门槛无关（探针那次报"无 token 到达"是
  `kv-pages 512` 装不下 6009+16 的容量拒绝——新 `capacity` 语义正确生效）。

## 六、下一步

1. **门槛按场景分流**：批内有 decode 行 / span 数多时用 64，纯大 span 波用 256，
   把满载那 3% 收回来。
2. vLLM 热态同口径重测（本次对比表沿用 `5.72 turns/s / 148ms / 15.0ms / 71%`，
   但那组未清缓存，口径偏乐观）。
