# 混合步时间预算闸门（26ms + 行数门 32）——2026-11-09

## 0. 结论

mix_cap 4096 买 Agent 场景（c=8 turns ×2.6）留下的满负荷 ITL p99 代价（41-42.5）由
**时间预算闸门**收口：`mix_budget_ms = 26.0` + `mix_budget_rows = 32`（仅高并发绑定）。

|---|---|---|---|---|---|
| 关（mix4096 旧默认） | 4364.5 / 4466.3 | 20.51 / 19.98 | 42.02 / 40.72 | 69.2 / — | 122.5 / 118.5 |
| **26ms+行数门（新默认）** | 4455.1 / 4284.0 | 19.70 / 20.84 | **31.37 / 32.62** | 60.4 / — | 137.2 / 146.3 |

- **ITL p99 41.4→32.0（−23%，2×2 交叉方向稳定）**，vs vLLM 38.5 领先 17%；
- TTFT p99 120→142（+18% 代价，4/4 方向稳定）——仍低于 vLLM 的 TTFT p50 144；
- tps / ITL p50 在漂移带内无差（当夜漂移 ±2-4%，g26 与关档各 2 发均值 −1%）；
- 30ms 档收益减半（p99 −7%）且 TTFT 代价小（+3ms）——保守备选；
- 全量 battery 归档 `battery-20261109-205320`：图档满载 4297.7 @ ITL 20.65 / **p99 32.64** /
  TTFT 63.6/140.5；轻载图档 11.23/12.70 不受影响。

## 1. 机制（crates/wein-sched/src/lib.rs）

- est_ms(d, p) = MIX_BASE_MS(12.0) + MIX_TOK_MS(0.040)·(d+p) + MIX_ROW_MS(0.050)·d，
  系数由实测曲线标定（m=1 gemm 8.23ms 地板、m≤128 边际 25.7µs/token、每 decode 行
  递推状态 ~50MB）；校验 c=100 est 21.0 vs 实测 20.74 ✓。
- `plan()` 相位一（decode 落位）后折算 prefill 许可 = (budget − est_decode)/MIX_TOK_MS，
  与 mix_cap 双闸门取更小；许可为正时下限 PREFILL_MIN。
- **行数门 mix_budget_rows = 32**：decode 行数 < 32 时闸门完全不生效。
- CLI：`--mix-budget-ms F` / `--mix-budget-rows N`（battery/调参覆盖用）。

## 2. 为什么必须行数门（无门版全负，已证伪）

无行数门（有 decode 就绑定）在 Agent 场景 c=8（4096 页/ctx32768/graph/DRAM on，各 2 发）：

| c=8 | turns/s | 命中 | ITL med | ITL p95 | ttft_hot |
|---|---|---|---|---|---|
| 关 | 1.475/1.799 | 0.464/0.644 | 17.8/16.8 | 21.2/20.4 | 326/499 |
| 30ms 无门 | 1.086/1.035 | 0.329/0.360 | 20.6/21.7 | **64.2/69.9** | 1674/1523 |
| 26ms 无门 | 1.034/1.020 | 0.470/0.463 | 21.2/20.8 | 58.7/64.9 | 938/1744 |

c=4：turns −19%、ttft_hot ×2。两个失效模式：
1. **模型斜率低估**：Agent 长上下文 prefill 实际边际 ~70µs/token（6009 冷实测外推），
   模型 40µs ⇒ 步长超标 60%+，ITL p95 反而 3×。
2. **微切片破坏快照粗栅格**：SNAP_KEEP_GRID 深锚依赖 chunk 尾落在 2048 格点
   （chunk_size 对齐）；预算切片（c=8 许可 ~430 token/步）把 chunk 尾挪出格点 ⇒
   深锚永不失火 ⇒ 命中 −17pt ⇒ prefill 量反增 ⇒ 恶性循环。
行数门后 c=8 验证发：turns 1.564 / 命中 0.564 / med 18.33——关档带内 ✓。

## 3. 满载 p99 的力学

c=100 稳态：重准入 prefill（~300 token prompt）与 99-100 decode 行同步。26ms 档许可
= (26 − 21)/0.04 ≈ 125 token/步 ⇒ 一个 prompt 拆 3 步 × ~26ms，搭乘 decode 行的
p99 由单步 42ms 变 26-32ms；TTFT 端多付 2 步基底（权重重读）⇒ TTFT p99 +20ms。
爬坡期（decode < 32）不绑定 ⇒ ramp 不受损。

## 5. 遗留

- 行数门 32 是经验值（Agent ≤16 与满载 100 之间）；中并发 32-64 未扫。
- 时间模型斜率对长上下文 prefill 失真（40 vs 70µs）——若未来要对低并发也开闸，
  需按"上下文深度→斜率"分段标定，或按实测步时反馈校正（EMA）。
