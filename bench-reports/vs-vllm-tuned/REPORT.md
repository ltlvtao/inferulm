# vLLM 0.32.0 调优扫参 · RTX 4090 24G / WSL 能力上限（Pareto 基线）

2026-10-31｜只测量，未改 wein 任何源码。GPU 一次一进程（起服前 `pgrep vllm` 为空、显存回落到
≈790 MiB；停服后复核进程组已杀、显存回落）。每档 3 次取中位；**同轮重跑默认档 3 次**作为漂移标尺。
扫描脚本 `bench/vs_vllm_tuned.sh`（27 档）、汇总 `bench/summarize_tuned.py`。

## 0. 口径与两个必须先说的发现

| 项 | 值 |
|---|---|
| GPU / 驱动 | RTX 4090 24GB（无 MIG）／610.88；SM 满载 2805–2820 MHz（空闲 2595），全档 `clocks.sm` 采样无降频 |
| vLLM / torch | 0.32.0 / 2.13.0+cu130，V1 引擎，V2 Model Runner，`FLASH_ATTN` 注意力后端 |
| 模型 | `~/.cache/wein/Qwen3.5-4B-text` + `--hf-overrides {"architectures":["Qwen3_5ForCausalLM"]}`，bf16 |
| 固定项 | `--max-model-len 8192`（全档）；`VLLM_USE_FLASHINFER_SAMPLER=0`；`VLLM_SERVER_DEV_MODE=1`（只为冷跑前 `/reset_prefix_cache`） |
| 代理 | 每档 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY all_proxy no_proxy`；`PATH` 剥掉 `/mnt/c/*`（Windows `ninja.exe` 在 interop 下 EACCES） |
| 尺度 | wein-bench（短上下文 c=4 / c=100）+ `longctx_probe.py`（3009/6009 token，冷/热，tokenizer 精确计数） |
| 默认档定义 | `--max-num-batched-tokens 2048 --max-num-seqs 256 --gpu-memory-utilization 0.9`（0.9 = vLLM 自身默认；上一轮基线用的是 0.85） |

**发现 A — 上一轮基线完全可复现，无环境漂移。** 用上一轮口径（0.85）重跑：满载 tps **3366**、ITL p50 25.47、
TTFT p50 137.9、3009/6009 冷 TTFT **200.6/396.3**，对上已知读数 3306.9 / 25.41 / 171.5 / 197.5 / 394.8。
所以 5% 阈值成立，下表 Δ% 可与旧报告直接连线。

**发现 B — `--gpu-memory-utilization 0.9` 在这台机器上本身就是个坑（且不稳定）。** 0.9 让 KV 涨到
291,188 token / 782 block，满载窗口峰值显存 **24062 MiB / 24564（剩 500 MiB）**，之后出现两种病态：
(i) 同一份配置重复跑，满载 tps 在 2751 / 2849 / 3019 之间摆（±5%），轻载 c=4 tps 在 119 / 135 / 255 之间摆（**±50%**）；
(ii) 部分整档落进"坏态"（`flashinfer`/`flashinfer-r2` 两次、`default-r2`、`default-r3`、`ssmbf16` 首跑的冷跑），
轻载 ITL 直接翻倍、tps 砍半，GPU 功耗只有 185 W（说明是主机侧喂不上数据，不是 GPU 慢）。
**判定：0.9 不是可用工作点；0.85 及以下 22 档全部稳定在 3308–3366 tps（离散 <2%）。**

## 5. 逐项判定（有效 / 无效 / N/A）

| # | 变量 | 判定 | 依据（Δ% 相对默认档） |
|---|---|---|---|
| ① | `--gpu-memory-utilization` 0.9 vs 0.85 vs 0.8 | **最强的单项杠杆，但方向与直觉相反：0.9 该降** | 0.85：满载 tps +18.1%、ITL p50 -10.2%、TTFT p50 -24.3%、冷 3009 -16.1%；0.8 与 0.85 打平（3339 vs 3366）。0.9→0.85 只是把峰值显存从 24062 降到 22661 MiB（离墙 1.9 GiB） |

| ④ | `--async-scheduling` | **默认已开；显式关掉会变差** | 默认（auto）= 开（`config/vllm.py:1585-1644`）；`--no-async-scheduling`：满载 tps 3006、轻载 ITL 13.69 (+12.5%)、轻载 tps 232 (-9%)。`--async-scheduling` 显式开 = 默认，不另立档 |
| ⑤ | `torch.compile -O3` | **不存在"O3"这个档：默认就是 VLLM_COMPILE(3)** | `{"level":3}` 被 pydantic 拒（`Unexpected keyword argument`，字段名是 `mode`）；`{"mode":3}` = 默认值。显式写出的 `compO3` 档读数 2593 tps / ITL 30.13，低于同几何的 default —— 说明 0.9 工作点下"同配置重复"本身就有 ±9% 抖动（见 §0-B） |
| ⑥ | 注意力后端 FLASHINFER | **N/A（本机不可用）；`VLLM_ATTENTION_BACKEND` 环境变量在 0.32.0 是 no-op** | `--attention-backend FLASHINFER` → `subprocess.CalledProcessError: … ninja … ` → `#error "CUDA compiler and CUDA toolkit headers are incompatible"`（flashinfer 0.7.0 的内核要 JIT，venv 里只有 nvcc **13.4**，torch 是 cu130）。环境变量写法两档都被 vLLM 自己报 `Unknown vLLM environment variable detected: VLLM_ATTENTION_BACKEND`，实际后端仍是 `FLASH_ATTN`；这两档的 2–3× 慢是主机侧坏态（GPU 仅 185 W），不代表 FLASHINFER |
| ⑦ | `--no-enable-chunked-prefill` | **原样不可用（N/A）；配合关 prefix caching 后可跑，结论：分块不是瓶颈** | 原样：`Assertion failed, Chunked prefill is required for mamba cache mode 'align'`。`nochunk-nopc`（同时 `--no-enable-prefix-caching`、mbt 8192）：6009 冷 **373.9** vs `mbt8192`（仍分块）**382.8** —— 差 2.3%，在噪声内；代价是前缀缓存全失效 |
| ⑧ | cudagraph 桶集是否要覆盖 c=100 | **默认已够（100 落到 104 桶）；给精确 100 + 精简桶只省显存** | 默认桶集 `1,2,4,8,16,24,32,…,512`（51 桶）；`cg100` 13 桶含 100：满载 tps 3330 vs 同侪 3333–3366（无差），峰值显存 22742（-5.5%），命中/ITL 无变化。**它进组合是为了省显存，不是为了桶** |
| ⑨ | `--mamba-ssm-cache-dtype bfloat16` | **满载/尾延迟的最强单项（+43.6% tps），但要接受 block 变细** | block_size 528→272、nblk 1518、KV 336,093 token（+27.6%）；满载 tps 4091、ITL p50 20.06（-29.3%）、p99 38.53（-49.0%）、热 TTFT 31.8/34.0（-18%/-15%）、命中 2992/5984（99%+）；冷 prefill 与默认同档（204–220/405–418 ms）。首跑的 1688/2618 ms 未复现 |
| ⑩ | `--quantization fp8`（在线 W8A8） | **全面有效**（见 §4） | 轻载/满载/长上下文全轴变快，KV 多 28.8% |

## 6. 默认档离上限差多少（结论）

| 指标 | 默认档（0.9, mbt 2048） | 本硬件上限（组合档） | 差距 |
|---|---|---|---|
| 满载 ITL p50 | 28.35 ms | **17.66 ms** | 默认是上限的 1.60×，有 37.7% 可提 |
| 满载 ITL p99 | 75.49 ms | **35.28 ms** | 2.14×，可提 53.3% |
| 满载 tps | 2849 | **4455** | 可提 **56.4%** |
| 满载 TTFT p50 / p99 | 182.2 / 271.3 | **150.5 / 190.1** | 17.4% / 29.9% |
| 轻载 c=4 ITL p50 / p99 | 12.17 / 17.26 | **8.21 / 9.88** | 32.5% / 42.8% |
| 轻载 c=4 tps | 255 | **333** | 30.7% |
| 3009 冷 / 热 TTFT | 239.0 / 38.7 | **148.7 / 31.1** | 37.8% / 19.8% |
| 6009 冷 / 热 TTFT | 467.2 / 39.9 | **285.3 / 34.1** | 38.9% / 14.7% |
| 峰值显存 | 24062 MiB | 21572 MiB | 少占 10.3% |

增量的来源按大小排序：`--quantization fp8`（约 +24% tps / -33% 冷 TTFT）、`gpu-mem 0.9→0.85`（+18% tps，且消除不稳定）、
`mamba-ssm bf16`（单独一档 +43.6% tps；叠进组合后 3539→4455 即 +25.9% tps、ITL p50 23.72→17.66 即 -25.5%）、
`mbt 8192`（-19% 3009 冷 TTFT）、图桶精简（-10% 显存）。其余单变量在 ±5% 内。

## 7. 测量有效性

- **每档独立起服**（无热缓存泄漏），每档 3 次取中位；`long-*.json` 里保留每次请求的逐 token 时间戳与
  `metrics_delta`（证明冷跑 `prefix_cache_hits=0`、热跑命中 2640/5808 等）。
- **漂移标尺**：默认档 3 次（`default` / `default-r2` / `default-r3`）+ 上一轮口径 `mem85`。`mem85` 与上一轮吻合到 2% 内 ⇒ 无跨轮漂移；
  默认档自身在 2751–3019 tps 间摆 ⇒ **0.9 工作点不可用作精细比较的基准**，故 §1 的 0.85 及以下各档同时互相校验（3308–3366，离散 <2%）。
- **坏态**（4/27 档命中）：特征是 GPU 功耗骤降到 ~185 W、轻载 ITL 翻倍，SM 时钟正常 ⇒ 主机侧（WSL/Windows）喂不上数据。
  已用复跑区分：`ssmbf16` 首跑冷 prefill 1688 ms → r2/r3 为 204/220 ms；`flashinfer` 两档的慢无法归因于配置（环境变量是 no-op）。
- 未锁时钟（WSL 不允许）；全档记录了 `clocks.sm` 最低值（2805–2820 MHz）与温度，无热降频。
