## 2. 两处改动（都保位级合同）

### 2.1 norm 载入成组（`block_sum_strided` / `rms_norm_zc` / `add_norm_zc`）
单块 1 行 norm 的墙是"单块喂不满 MLP"：旧循环 `i += bdim` 逐元素载入，10 次
串行 stall。改成**成组先发独立载入、再按 i 升序累加**（8 发一组 for 求和与
rms_norm 输出段、4 发一组 for add_norm 的两段），算术序与归约树一字未动。
读数：`rms_norm_zc` 3.70 → **1.43 µs/发**（2.6×）、`add_norm_zc` 6.29 → **4.47**。

### 2.2 尾残差 add + 下一层 ln1 的 norm → 一发 `add_norm_zc`
旧拓扑每层是 `[ln1 norm] … [add_norm site A] … [add site B]` 三发（site B 当年
刻意不融合）。现在 site B 直接把"残差 + **下一层** ln1"合成一发（写 x 与下一层
的 n1），只有第一层的 ln1 留在循环外。
位级：`add_norm_zc` 的 sum 落 bf16 后再累加平方，与 add→norm 两发分离路径同序同式
⇒ **逐位同**（`WEIN_ATTN_V3=0` 下 b2 混批位级档逐字节同佐证）。

发数账：32 ln1 + 31 add + 32 siteA + 1 尾 = 96 → 1 + 64 + 1 = 66（**−31 发/步**）。

## 4. 下一步的判决（数据说话）

c=1 每步 10.80ms 的构成：gemv 9.93ms（8.41GB 权重 @ 845GB/s）+ 小算子 0.66ms
+ 0.2ms 其它。vLLM 同口径 10.31ms（gemv 9.62 @ 874GB/s + 小算子 0.53 + 0.21）。

- 追平需要 **gemv 874GB/s（−0.31ms）** 且 **小算子砍到 0.5ms（−0.16ms）**。
- 小算子侧的现实上限：剩下 12 类里 9 类已经是 1.0-1.8µs/发（1 道访存相位的
  地板），只有 `add_norm_zc`(4.47) / `dn_qk_l2norm`(2.56) / `attn_combine`(3.34)
  还有 2-3× 空间，合计 ~150µs。要再往下只能把 norm/silu 折进 gemv 的前导，
  代价是 A 侧 L2 冗余（每块多读一整个 x 行 + w，实测 ≈ +0.9GB/步）且 norm
  归约树要换形（破位级合同）——净收益估算在 ±0.1ms 内，**不划算**。
- **结论：c=1 这条轴的 ROI 已经很低（剩余 ~0.5ms 全是硬结构），建议收手**，
  把力气移到满载（ITL 21.1 vs 19.1，我们落后 10%）与需求侧。
